## QR 생성기

QR은 "생성됐다"와 "읽힌다"가 다르다. 브랜드 색을 그대로 쓰면 모듈과 배경의 밝기 차이가 모자라 인식이 흔들리는데, 화면으로는 멀쩡해 보여서 인쇄하고 나서야 알게 된다.

| 브랜드 색 | 흰 배경 대비 | 대신 쓰는 색 |
|---|---|---|
| 네이버 `#03C75A` | 2.2 : 1 — 위험 | `#0B5E3B` |
| 유튜브 `#FF0000` | 4.0 : 1 — 적색 광원에서 뭉갬 | `#8C0B0B` |
| 카카오 `#FEE500` | 노랑은 모듈색으로 불가 | `#4A3B00` |

**웹 버전** ([`/qr/`](https://yj0631.github.io/AI/qr/)) — 두 색의 WCAG 대비비를 입력하는 즉시 계산하고, 모자라면 색상은 유지한 채 명도만 낮춘 대안을 제시한다. 사이트 프리셋 18개, 오류정정 기본 H, PNG·SVG 출력. 입력한 내용은 어디로도 전송되지 않는다.

**CLI 버전** (`qr-cli/`) — 사이트 별칭을 나열하면 한 번에 생성하고 전부를 한 장의 시트로 묶는다. WiFi·연락처·위치 QR과 인쇄용 SVG를 지원한다. 자세한 사용법은 [`qr-cli/README.md`](qr-cli/README.md).

```bash
python qr-cli/qrgen.py naver youtube instagram -d out/ --sheet out/sheet.png
```

## 카드뉴스

한 장에 한 메시지, 추상론 없이 숫자와 온도로. 주제마다 팔레트 계열을 완전히 다르게 잡아 같은 피드에 올려도 두 세트가 섞여 읽히지 않게 했다. 비율은 `data-ratio` 한 글자로 바뀌고 타입 스케일이 따라온다.

## 확인한 방법

만드는 것보다 여기에 시간이 더 들어갔고, 실제로 문제를 잡아낸 것도 전부 이쪽이다.

- **QR** — Playwright로 페이지를 조작해 캔버스를 뽑고 OpenCV로 다시 디코딩해 원문과 일치하는지 확인. 한글 포함 5건 통과
- **배포본** — 로컬에서 되고 배포본에서 깨지는 경우가 흔해, 같은 순회를 배포 주소로 다시 실행 (링크 7개·CDN·모바일 폭)
- **색** — 눈으로 고른 팔레트는 자주 틀린다. 카드뉴스는 배경이 순환해 색 하나가 여러 역할을 겸하므로, 5쌍의 대비를 전부 계산해 통과한 것만 쓴다

## 알려진 문제

`cardnews/`의 HTML은 `.card` 자신의 `padding`·`gap`에 `cqw` 단위를 쓰는데, CSS 컨테이너는 자기 자신을 질의할 수 없어 뷰포트 기준으로 계산된다. 그래서 브라우저 창이 넓을수록 여백이 부풀고 글자가 작아진다(1600px에서 제목 11.7px). `padding: 8.5%` / `gap: 4%`로 두 줄만 바꾸면 해결된다.
