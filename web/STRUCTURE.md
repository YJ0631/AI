# 반려견 소개 사이트 — 구조

강아지 여러 마리를 한 페이지에서 소개한다. 흰 배경, 장식 최소, 사진과 이름이 먼저 읽히는 것이 목표다.

상위 저장소 규약(`../STRUCTURE.md`)을 따른다 — HTML · CSS · JS만, 빌드 없음, 상대경로.

---

## 1. 파일

```
web/
├─ index.html      내용이 전부 여기 있다. 강아지를 추가·수정하는 곳
├─ style.css       색·서체 토큰이 맨 위 "교체 구역"에 모여 있다
├─ app.js          스와이퍼 + 사진 확대. 그 둘뿐이다
├─ STRUCTURE.md    이 문서
├─ README.md       고치는 방법
└─ photos/         로컬 사진으로 바꿀 때 쓰는 자리
```

## 2. 화면 구성

```
┌─ header.hero
│    .swiper        슬라이드 4장 — 사진 위에 이름·한 줄
│    .intro         사이트 제목과 소개 문단
│
├─ main
│    강아지 카드 6장   사진(왼쪽 220px) + 이름·견종·소개·태그·좋싫(오른쪽)
│    갤러리 4장        정사각형, 클릭하면 확대
│
└─ footer
```

**원페이지인 이유** — 강아지마다 페이지를 나누면 파일이 여섯 개로 늘고 방문자는 목록과 상세를 오가야 한다. 한 마리당 정보가 대여섯 줄인 지금은 한 페이지에 늘어놓는 편이 읽기도 고치기도 빠르다.

**카드가 세로 목록인 이유** — 3열 격자에 넣으면 사진은 예쁘지만 설명이 두 줄에서 잘린다. 가로형 카드는 사진과 글이 나란히 놓여 한 마리당 정보를 다 보여주면서도 위아래로 훑을 수 있다.

## 3. 스와이퍼

**라이브러리를 쓰지 않는다.** 가로 스크롤 + `scroll-snap-type: x mandatory`면 터치 관성, 휠, 트랙패드, 키보드 이동을 브라우저가 이미 처리한다. Swiper·Slick을 넣으면 그것들을 흉내 낸 15만 자짜리 코드를 대신 짊어지게 된다.

```css
.slides { overflow-x: auto; scroll-snap-type: x mandatory; }
.slide  { scroll-snap-align: center; }
```

JS가 맡는 것은 세 가지뿐이다 — **점 표시, 좌우 화살표, 자동 넘김**.

자동 넘김은 다음 경우에 멈춘다. 읽는 중에 화면이 바뀌는 것만큼 성가신 것이 없다.

| 조건 | 동작 |
|---|---|
| `prefers-reduced-motion: reduce` | 처음부터 돌지 않음 |
| 마우스를 올린 동안 | 멈춤 |
| 키보드 초점이 들어온 동안 | 멈춤 |
| 다른 탭을 보는 동안 | 멈춤 |

점 개수는 슬라이드 수를 세어 JS가 만든다. 슬라이드를 추가해도 HTML에서 점을 늘릴 필요가 없다.

**JS가 실패해도 첫 슬라이드는 그대로 보인다.** 스와이퍼가 죽으면 사진 한 장과 글이 남을 뿐, 빈 화면이 되지 않는다.

좁은 화면(620px 이하)에서는 화살표를 감춘다. 손가락으로 넘기는 편이 빠르고, 버튼이 사진을 가린다.

## 4. 사진

지금은 [Unsplash](https://unsplash.com/) 사진을 주소로 직접 불러온다. 실물 사진이 준비되기 전까지 배치와 크기를 확인하기 위한 것이다.

```
https://images.unsplash.com/photo-XXXX?auto=format&fit=crop&w=800&h=800&q=70
```

| 매개변수 | 뜻 |
|---|---|
| `w` · `h` | 내려받을 크기. 카드 800×800, 슬라이드 폭 1600 |
| `fit=crop` | 비율이 다르면 잘라낸다 (찌그러뜨리지 않는다) |
| `auto=format` | 브라우저가 지원하면 WebP로 준다 |
| `q` | 화질 70 전후면 눈에 띄는 손실 없이 용량이 절반이다 |

**주의 — 사진과 설명이 맞는지 직접 보고 확인해야 한다.** 실제로 이 페이지에서 "래브라도"라고 적힌 자리에 포인터 사진이, "보더 콜리" 자리에 오스트레일리안 셰퍼드 사진이 들어가 있었다. 주소만으로는 무엇이 찍혀 있는지 알 수 없다.

**내 사진으로 바꿀 때** — `photos/`에 넣고 `index.html`의 `src`를 `photos/보리.jpg`로 바꾼다. 그 외에 고칠 것은 없다.

첫 슬라이드 사진에는 `loading="lazy"`를 붙이지 않는다. 화면에 바로 보이는 사진을 지연 로딩하면 오히려 늦게 뜬다.

## 5. 색과 대비

흰 배경 고정이다. `color-scheme: light`를 명시해 시스템이 다크 모드여도 스크롤바와 폼까지 흰 바탕에 맞춰 그려지게 한다. 사진이 주인공인 페이지에서 바탕이 바뀌면 같은 사진이 다른 톤으로 보인다.

| 용도 | 값 | 흰 배경 대비 |
|---|---|---|
| 본문 | `#111111` | 18.9 : 1 |
| 보조 설명 | `#5A5A5A` | 7.0 : 1 |
| 강조 | `#1552CC` | 7.6 : 1 |
| 경계선 | `#E6E6E6` | — |

보조 설명까지 7:1을 넘겼다. 흰 배경 위 옅은 회색 글씨는 시안에서는 멀쩡하고 실제 화면에서는 읽히지 않는다.

슬라이드 글씨는 사진 위에 올라가므로 대비를 색으로 보장할 수 없다. 어두운 그러데이션(`--scrim`)을 깔아 어떤 사진이 와도 흰 글씨가 읽히게 한다.

## 6. 반응형

| 폭 | 카드 | 화살표 | 갤러리 |
|---|---|---|---|
| ~ 620px | 사진 위, 글 아래 | 감춤 | `auto-fit` 1~2열 |
| 621 ~ 700px | 사진 위, 글 아래 | 표시 | 2~3열 |
| 701px ~ | 사진 왼쪽 220px + 글 | 표시 | 3~4열 |

갤러리는 `repeat(auto-fit, minmax(180px, 1fr))` 한 줄로 처리한다. 장수마다 중단점을 따로 잡지 않는다.

## 7. 강아지 추가하기

`index.html`에서 `<article class="dog">` 하나를 복사해 붙이고 내용만 바꾼다. CSS도 JS도 건드리지 않는다.

```html
<article class="dog">
  <div class="dog-photo">
    <img src="…" alt="보리 — 골든 리트리버" loading="lazy">
  </div>
  <div class="dog-body">
    <div class="dog-head">
      <h3>보리</h3>
      <p class="breed">골든 리트리버 · 남아 · 4살</p>
    </div>
    <p class="say">한 줄 소개</p>
    <ul class="tags"><li>태그</li><li>태그</li></ul>
    <dl class="mini">
      <div><dt>좋아하는 것</dt><dd>…</dd></div>
      <div><dt>싫어하는 것</dt><dd>…</dd></div>
    </dl>
  </div>
</article>
```

머릿수를 적어 둔 `.count`(`<span>6</span>마리`)도 같이 고친다. JS가 세지 않는다 — 세게 만들 수는 있지만, 여섯 줄짜리 목록에 그만한 코드를 두는 것이 아깝다.

슬라이드를 늘릴 때는 `<li class="slide">`를 복사한다. 점은 저절로 따라온다.
